# 코어 루프 (2026-08-16)

[[손맛 샌드박스]]가 쏘는 맛만 보던 무대였다면, 여기서는 그 위에 판이 얹혔다.
웨이브가 밀려오고, 못 잡으면 아프고, 죽으면 정산하고 다시 오른다.

## 판의 모양

스테이지 하나는 **웨이브 10개 + 보스**다. 보스를 잡으면 클리어 화면을 거쳐 다음 스테이지로 가고,
체력이 다하면 스크랩을 정산한 뒤 **스테이지 1부터** 다시 시작한다(로그라이트).

압박의 축은 방어선이다. 화면 아래쪽 선(`FIELD.DEFENSE_LINE_Y`)을 적이 넘으면 체력이 깎인다.
이 피해는 무적 시간으로 막히지 않는다. 못 잡으면 아프다는 것이 이 게임의 코어이기 때문이다.
반대로 기체와 직접 부딪히는 피해는 짧은 무적을 준다. 그래야 한 번의 실수가 연쇄로 번지지 않는다.

보스전은 체력전이 아니라 **시간전**이다. 보스는 아주 천천히 내려오고, 방어선에 닿는 순간 기체를 깔아뭉갠다.
스테이지 1 기준으로 처치까지 17초쯤, 보스가 내려오는 데 27초쯤 걸린다. 그 10초의 여유가 난이도다.

## 상태 흐름

`src/combat/game.js`의 `STATE`가 전부다. 프레임워크 없이 문자열 상수와 `switch` 하나로 돌린다.

```
WAVE ──(전멸)──> WAVE_REST ──> WAVE(+1)
  └─(웨이브 10 전멸)─> BOSS_WARNING ─> BOSS
                                        ├─(격파)─> BOSS_DEATH ─> STAGE_CLEAR ─[다음 스테이지]─> WAVE
                                        └─(방어선 도달)─┐
  체력 0 ────────────────────────────────────────────> PLAYER_DEATH ─> GAME_OVER ─[다시 도전]─> WAVE(스테이지 1)
```

- `WAVE`: 스폰 목록을 간격을 두고 한 기씩 내보낸다. 목록이 비고 화면도 비면 끝.
- `WAVE_REST`: 숨 돌리는 짧은 사이. 다음 웨이브 배너가 여기서 뜬다.
- `BOSS_WARNING`: 붉게 깜빡이는 경고와 잔잔한 흔들림. 배경 장식 정거장은 이때 숨긴다.
- `BOSS_DEATH`: 다단 폭발. 보스가 있던 자리 여기저기서 아홉 번 연달아 터진다.
- `PLAYER_DEATH`: 기체를 지우고 파편을 네 번 터뜨린 뒤 결과 화면으로 넘긴다.

`COMBAT_STATES`에 든 상태에서만 적이 움직이고 발칸이 나간다. 나머지는 연출과 입력 대기다.

## 웨이브 난이도 규칙

규칙은 두 겹이다. **무엇이 나오는가**와 **얼마나 세지는가**를 나눠 뒀다.

| 어디 | 무엇 |
| --- | --- |
| `src/combat/tuning.js`의 `WAVE_TABLE` | 웨이브 1~10에 어떤 적이 몇 기 나오는지(스테이지 1 기준) |
| `src/combat/tuning.js`의 `STAGE` | 스테이지가 오를 때 곱해지는 배수(HP·수·속도·스폰 간격·스크랩) |
| `src/combat/tuning.js`의 `ENEMY_TYPES` | 적 3종의 HP·속도·판정 반지름·통과 피해·스크랩 |
| `src/combat/waves.js` | 위 둘을 곱해 실제 스폰 목록으로 바꾸는 계산 |

스테이지 n의 배수는 전부 1차식이다. HP는 `1 + 0.4×(n-1)`, 수는 `1 + 0.15×(n-1)`,
속도는 `1 + 0.05×(n-1)`, 스폰 간격은 `0.92^(n-1)`. 보스 HP는 `1 + 0.45×(n-1)`.

적 3종의 성격:

- **인터셉터**: HP 3, 빠르고 다수. 웨이브의 뼈대.
- **건쉽**: HP 12, 느리고 단단하다. 통과 피해 16으로 가장 아프다.
- **원반**: HP 6, 좌우로 흔들리며 내려와 조준을 흔든다.

## localStorage 키

`tuning.js`의 `STORAGE_KEYS`에 모아 뒀다. 아웃게임 상점이 이 값을 읽어 간다.

| 키 | 뜻 |
| --- | --- |
| `starstrike.totalScrap` | 누적 스크랩. 스테이지 클리어와 사망 때 정산된다. |
| `starstrike.bestStage` | 최고 도달 스테이지 |
| `starstrike.bestWave` | 그 스테이지에서 도달한 웨이브 |

정산은 **스테이지 단위**다. 이번 스테이지에 모은 몫(`stageScrap`)을 클리어나 사망 때 한 번만 누적에 넣는다.
같은 몫을 두 번 세지 않도록 넣은 뒤 0으로 비운다.

## 화면 구성

마크업과 모양은 `index.html`, 값 갱신은 `src/combat/ui.js`가 맡는다.
`ui.js`는 게임 규칙을 전혀 모른다. `game.js`가 시키는 대로 그린다.

- 인게임 HUD: 왼쪽 위에 스테이지·웨이브와 체력 바, 오른쪽 위에 스크랩. 보스전에는 아래에 붉은 보스 체력 바.
- 스테이지 클리어: 획득 스크랩, 누적 스크랩, [다음 스테이지].
- 사망 결과: 도달 지점, 이번 판 스크랩, 누적, 최고 기록, [다시 도전].

## 짚어 둘 것

- 보스는 피격 시 몸통을 흰 재질로 갈아 끼우지 않는다. 초당 열 발을 맞는 동안 내내 하얀 덩어리로 보이기 때문이다.
  대신 맞은 자리에 작은 불꽃을 튀긴다. 적기(작고 금방 죽는다)는 지금처럼 몸통 번쩍임이 맞다.
- 배경 장식으로 두던 정거장은 그대로 두되, 보스전 동안에는 숨긴다. 실제로 싸우는 보스는 별도 인스턴스다.
- 상태를 넘길 때마다 `#clearField()`로 탄·적·파편·스크랩·보스를 전부 거둔다. 재시작을 반복해도 잔상이 남지 않는다.
- 손맛 샌드박스의 `src/combat/sandbox.js`는 `src/combat/game.js`로 자라며 사라졌다.

## 남은 일

- **머지 보드**: 화면 아래쪽 절반. 지금은 비어 있다. 다음 작업이다.

- **광고 버튼**: 클리어 화면의 "스크랩 3배 (광고)" 버튼은 자리만 잡아 뒀다(`#btn-ad-scrap`, 비활성).
  [[기획 검토와 개선안]] 4절대로 AdProvider 인터페이스를 먼저 세우고 가짜 광고로 루프를 검증한다.
- **밸런스**: 지금 규칙으로는 스테이지 3쯤에서 벽에 부딪힌다. 상점이 붙어야 이 벽이 뚫린다.
  벽의 높이는 `STAGE`와 `BOSS`의 배수로 조절한다.
- **보스 처치 후 버프 선택**: [[기획 검토와 개선안]] 3절의 후순위 제안. 상태 기계에 `STAGE_CLEAR` 앞뒤로 끼우면 된다.
