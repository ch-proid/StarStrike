# 기획 검토와 개선안 (2026-08-16)

[[기획안 정리]]를 바탕으로 코어 루프, 손맛, 수익화를 검토한 결과다.

## 1. 단일 장착 구조의 약점 (가장 중요)

- 문제: 최고 레벨 무기 1개만 쏘면, 보드의 나머지 무기는 전투에 아무 기여를 못 한다. 합성이 "장착 무기가 바뀌는 순간"에만 보상으로 느껴지고, 중간 합성은 밋밋해진다.
- 개선안: 주포(최고 레벨)는 강하게 쏘되, 보드의 나머지 무기 합산 공격력의 20~30%를 보조 화력으로 더한다. 주포 1개의 직관적 타격감은 지키면서, 모든 합성이 곧바로 화력 상승으로 느껴진다.
- 결정 필요: 보조 화력을 실제 탄환으로 보여줄지, 수치 보너스로만 넣을지.

## 2. 손맛 검증 계획

시스템을 쌓기 전에 손맛부터 확인해야 한다. 더미 적 1종 + 발칸 1종만 있는 "손맛 샌드박스"를 먼저 만들어 아래 요소를 튜닝한다.

- [ ] 적 피격 시 흰색 번쩍임
- [ ] 적 처치 시 짧은 멈춤(히트스톱 2~3프레임)과 화면 흔들림
- [ ] 총구 화염, 파괴 파티클
- [ ] 스크랩이 기체로 빨려 들어오는 자석 연출
- [ ] 합성 시 크기 팝 + 파티클
- [ ] 우주선 머리 방향 수정: 지금 데모에서 아래를 향하고 있음 → 위(적 방향)로

## 3. 코어 루프 페이싱

- 첫 죽음까지 1~2분. 짧게 죽고 빨리 다시 시작해야 훅이 걸린다.
- 첫 3판은 매판 퍽을 하나씩 살 수 있게 스크랩 곡선을 짠다. "죽어도 강해졌다"를 몸으로 느끼게.
- 보스 등장 전에 권장 화력을 보여줘서, 죽음이 억울하지 않고 "다음엔 이만큼 키워야겠다"로 이어지게 한다.
- 최고 웨이브 기록을 크게 보여준다. 자기 기록 갱신이 재도전의 동력이다.
- 후순위 제안: 보스 처치 후 3개 중 1개 버프 고르기. 로그라이트다운 "런마다 다른 재미"를 싸게 넣는 방법.

## 4. 광고 수익, 웹의 현실

기획의 수익화는 모바일 앱 기준이라 웹에서는 경로가 다르다.

- GitHub Pages에 직접 광고를 붙이기는 어렵다. 구글 H5 Games Ads가 웹 게임 보상형 광고를 지원하지만 승인 절차가 있고, 광고 차단기 때문에 수익의 30~40%가 새는 게 웹의 현실이다.
- 현실적인 길: Poki, CrazyGames 같은 웹 게임 포털 입점. 포털 SDK가 보상형 광고를 제공하고 수익을 나눠 주며, 유저 트래픽도 포털이 가져다준다. GitHub Pages는 개발·테스트·공유용으로 유지한다.
- 광고 제거 결제는 웹 결제 연동 부담이 커서 후순위.
- 설계 지침: 광고 호출을 AdProvider 인터페이스로 감싼다. 지금은 가짜 광고(3초 대기)로 루프만 검증하고, 포털 입점 때 SDK로 갈아 끼운다. 기획의 보상형 광고 4종(부활, 스크랩 3배, 무기 레벨업, 광고 제거)은 그대로 유효하다.

## 5. 작업 우선순위

1. 손맛 샌드박스 (발칸 + 더미 적 + 타격 연출 튜닝)
2. 코어 루프 (웨이브, 사망/재시작, 스크랩)
3. 머지 보드 (보조 화력 방식 결정 포함)
4. 아웃게임 퍽 상점
5. 보스와 밸런스
6. 웹 포털 입점 조사
