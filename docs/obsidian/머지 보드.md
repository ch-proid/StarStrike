# 머지 보드 (2026-08-16)

[[코어 루프]]가 판의 모양을 만들었다면, 여기서는 그 판을 이길 힘을 만든다.
화면 아래 보드에서 무기를 사고 겹쳐 키우면, 위에서 나가는 발칸이 곧바로 굵어진다.

## 화면을 나눈 방식

아래쪽 3분의 1이 보드다. `index.html`의 `#board`가 그 자리를 잡고,
3D 전장은 그만큼 위로 올라간다. 밀어 올리는 계산은 `src/main.js`의 `applyFraming()` 한 곳에 있다.

카메라 위치와 바라보는 점을 같은 값만큼 내리면 기울기와 거리는 그대로 두고 프레임만 옮길 수 있다.
얼마나 옮길지는 규칙 한 줄로 정한다. **보드 윗변이 방어선보다 `VIEW.BOARD_TOP_MARGIN`만큼 아래에 온다.**
보드 높이를 실제로 재서 쓰기 때문에, 창 크기가 바뀌면 리사이즈에서 다시 잡는다.

전장이 짧아진 만큼 적 속도(`ENEMY_TYPES`)를 15%쯤 낮췄다. 화면에 들어와 방어선에 닿기까지의
시간은 예전과 비슷하게 남는다. 보스도 `SPAWN_Y`를 8.2로 내리고 하강 속도를 0.3으로 늦춰,
방어선까지 27초라는 원래 약속을 지켰다.

층위는 이렇게 겹친다. 보드(5) < HUD·배너(10) < 결과 화면(20) < 끌고 있는 무기(40).
그래서 클리어와 사망 화면은 보드를 덮고, 정산 중에는 보드를 만질 수 없다.

## 보조 화력 공식

**결정: 보조 화력은 실제 탄환이 아니라 수치 보너스다. 대신 주포 연출에 반드시 반영한다.**
([[기획 검토와 개선안]] 1절)

가장 레벨이 높은 무기 하나가 주포다. 나머지는 쏘지 않는 대신 합산 공격력의 일부를 얹어 준다.

```
무기 공격력 = BASE_POWER × POWER_PER_LEVEL ^ (레벨 - 1)      // 1 × 1.6^(n-1)
총 공격력   = 주포 공격력 + (나머지 합산 × SUPPORT_RATIO)     // 나머지의 25%
```

레벨 1 무기 하나면 총 공격력이 정확히 1이고, 그때의 발칸은 예전 그대로다(초당 10발 × 대미지 1).
보드를 다 비워도 `MIN_POWER`(0.35)만큼은 남는다. 기체에 달린 예비 발칸인 셈이다.

초당 피해량은 총 공격력에 **정비례**한다. 그 몫을 연사와 한 발의 무게로 나눠 갖는다.

```
연사 배수    = 총 공격력 ^ FIRE_RATE_EXP  (FIRE_RATE_MAX에서 멈춤)
한 발 대미지 = BULLET_DAMAGE × 총 공격력 ÷ 연사 배수
```

굵기·길이·색은 총 공격력의 **로그**에 걸려 있다. 구간 계단이 아니라 연속 보간이라,
합성 한 번마다 탄이 조금씩 두꺼워지고 색이 시안 → 보라 → 금색으로 옮겨 간다.
탄 재질을 공유 캐시에서 꺼내지 않고 `Vulcan` 전용으로 만든 이유가 이것이다.

합성하는 순간에는 기체가 푸르게 번쩍이며 살짝 부풀고, 둘레에서 빛무리가 터지고, 화면이 짧게 흔들린다.
수치 보너스라도 몸으로 느껴야 하기 때문이다.

## 조작

| 놓은 자리 | 일어나는 일 |
| --- | --- |
| 같은 레벨 위 | 합성. 한 레벨 위로 올라가고 원래 칸은 빈다. 번쩍임 + 크기 팝. |
| 다른 레벨 위 | 자리 맞바꿈 |
| 빈 칸 | 이동 |
| 휴지통 | 분해. 레벨에 따라 스크랩을 돌려받는다. |
| 보드 밖 | 아무 일도 없다 |

포인터 이벤트 하나로 마우스와 터치를 함께 받는다. 칸 위치는 집어 드는 순간 한 번만 재 둔다.
끄는 동안 보드는 움직이지 않기 때문이다.

무기를 끌고 있는 동안에는 기체가 따라 움직이면 안 된다. `board.js`가 내보내는 `boardInput.dragging`을
`ship.js`가 보고 그때의 손짓을 흘려보낸다. 보드 위에서 시작된 입력도 마찬가지다.

## 인게임 경제

스크랩 카운터가 곧 지갑이다. 다만 세는 갈래가 둘이다.

- `wallet`: 지금 쓸 수 있는 돈. 무기를 사면 줄고, 분해하면 는다. HUD에 보이는 숫자다.
- `runScrap`: 이번 판에 **번** 총량. 결과 화면과 누적 저장은 이쪽을 쓴다.

쓴 돈을 누적에서 다시 빼지 않는다. 후한 셈이지만 일부러 그렇게 뒀다. 초반 성장 체감을 위해서다.

가격은 `BUY_COST`(20)에서 시작해 살 때마다 `BUY_COST_GROWTH`(1.35)만큼 오른다.
이 누적은 **한 판 안에서만** 산다. 죽으면 보드와 함께 가격도 처음으로 돌아간다.
판을 시작할 때 레벨 1 무기 하나를 공짜로 준다. 주포가 비는 상황을 막기 위해서다.

살 수 없을 때는 버튼이 꺼지고 머리줄에 까닭이 뜬다. "스크랩 N 더 모으면 살 수 있다" 또는
"보드가 가득 찼다". 보드가 꽉 찼을 때의 보상형 광고는 `#btn-ad-merge`로 자리만 잡아 뒀다.

## 수치가 있는 곳

전부 `src/combat/tuning.js` 한 곳이다.

| 상수 | 무엇 |
| --- | --- |
| `BOARD` | 칸 수(4 × 3). 바꾸면 그리드 모양도 따라 바뀐다. |
| `WEAPON` | 레벨당 공격력 배수, 보조 비율, 구매 가격과 환급, 시작 무기 레벨 |
| `VULCAN` | 연사 배분(`FIRE_RATE_EXP`, `FIRE_RATE_MAX`)과 탄 연출 한계 |
| `VIEW` | 보드 높이에 맞춘 화면 구성 여유 |
| `PLAYER.POWER_*` | 합성 순간의 파워업 연출 |
| `BOSS.BASE_HP` | 보드를 키워야 할 이유를 정하는 손잡이 |

보드 높이 자체는 CSS(`#board`의 `clamp(190px, 33vh, 320px)`)에 있다. 화면 크기에 매인 값이라서다.

## 파일

| 어디 | 무엇 |
| --- | --- |
| `src/combat/board.js` | 칸 데이터 + 끌어다 놓기 + 표시. 재화는 물어보고 시킬 뿐 직접 만지지 않는다. |
| `src/combat/game.js` | 지갑을 들고 보드와 발칸을 잇는다. 합성 순간의 연출도 여기서 터뜨린다. |
| `src/combat/vulcan.js` | `setPower()`로 대미지·연사·굵기·색을 한꺼번에 갈아 끼운다. |
| `index.html` | 보드 마크업과 모양 |

## 짚어 둘 것

- 적 HP는 이제 반올림하지 않는다(`enemies.js`). 탄 한 발의 대미지가 화력에 따라 실수로 오르내리기 때문이다.
- 보스 HP를 170에서 460으로 올렸다. 예전 수치는 총 공격력 1을 기준으로 잡은 값이라,
  보드가 붙은 지금은 5초 만에 녹았다. 지금은 스테이지 1을 알뜰히 굴렸을 때(총 공격력 3쯤) 14초쯤 걸린다.
- 같은 최고 레벨이 둘이면 하나만 주포다. 나머지는 보조로 센다.
- 보드는 스테이지를 넘어가도 남는다. 죽을 때만 사라진다(로그라이트).

## 실측

브라우저에서 스테이지 1을 자동으로 굴려 본 결과다.

- 스테이지 1 한 판 약 114초. 보스 앞에서 총 공격력 3.2, 보스 처치 14초(내려오는 데 27초).
- 스테이지 2도 같은 흐름. 보스 앞 총 공격력 4.3, 처치 15초.
- 구매는 스테이지 1 동안 6~7번. 무기 7개면 레벨 3 + 2 + 1쯤으로 정리된다.

## 남은 일

- **아웃게임 퍽 상점**: 시작 무기 레벨, 시작 스크랩 같은 퍽이 붙으면 초반 곡선이 크게 바뀐다.
  누적 스크랩 키는 [[코어 루프]]의 표에 있다.
- **밸런스**: 화력은 기하급수로 크고 적 HP는 1차식으로 큰다. 스테이지가 깊어지면 이 둘이 어긋난다.
  `STAGE.HP_PER_STAGE`를 지수로 바꾸거나 `WEAPON.POWER_PER_LEVEL`을 낮추는 두 갈래가 있다.
- **보드 꽉 참 광고**: `#btn-ad-merge`는 아직 껍데기다.
  [[기획 검토와 개선안]] 4절대로 AdProvider를 먼저 세운다.
- **무기 테크 해금**: 레이저·미사일·플라즈마는 아웃게임에서 열린다. 지금은 발칸 한 종뿐이라
  타일 색만으로 레벨을 구분한다. 무기가 늘면 칸에 종류 표시가 필요하다.
